   - 원인은 `grid` 칸의 최소 폭이 긴 단어 길이로 잡히는 것이었어요. 카드에 `min-w-0` 한 줄로 고쳤고, 고친 뒤 26회 모두 0이었어요(`docs/plan.md` 6-5, 전후 표).
2. **화면 문구의 말투가 섞이고 내부 원인이 새어 나옴** · 2026-11-23 · `17951ae`(진단), `13d8627`(교체), `bb361db`(검사 테스트)

   - 전사본을 지우면 발언·근거·임베딩이 함께 지워지고 묶음과 기록은 남는다는 것을 DB의 외래 키(`on delete cascade`)로 확인해 문구에 사실만 쓰자고 제안했어요(결정 7). (누가 DB를 확인했는지는 확인 필요)
4. **전체 오류 화면은 입력과 결과를 지움** · 2026-11-23 · `8a18c8a`

5. **원문 보기에서 앱 안 이동 시 발언 스크롤이 깨짐** · 2026-11-23 · `0dc1760`

6. **개발 서버의 `Date.now()` 경고** · 2026-11-23 · `dfaeed0`, `0dc1760`
   - 화면은 정상인데 터미널에 반복해서 찍히던 경고를 `connection()` + `Suspense` 분리로 없앴어요. 뼈대와 실제 내용의 높이 차이는 0px로 측정했어요.
7. **클로바노트 제목의 콜론이 화자로 읽힐 위험** · 2026-11-23 · `19b31cb`

8. **"참가자 n명이 말했어요"는 시스템이 한 일보다 과장** · 2026-11-23 · `7d91578`, `defe0af`

9. **점검표를 쓰다가 문구와 동작이 달랐던 곳** · 2026-11-23 · `0a781e7`

10. **의도적 오류 데이터와 가짜 응답으로 "근거 없음" 경로 강제 확인** · 2026-11-20, 2026-11-23 · `b5dac6e`, `7d169ce`
    - 없는 번호·진행자 번호·뜻이 반대인 실제 발언(C-08)을 일부러 넣은 가짜 응답을 만들어, 코드가 잡는 것과 사람이 읽어야 아는 것을 나눠 보여 주게 했어요(사용성 테스트 재료).

## 2. 사람이 결정한 것 (초안: 본인 말로 고치세요)

AI가 선택지를 보여 주면 사람이 고르거나 바꾼 것이에요. 괄호는 기록에 남은 이유예요.

1. **핵심 흐름 1개만 만들고 뺀 기능을 정함** · 2026-11-19 · `38ad8da`
   - 전사본 → 주제 분류 → 근거 연결 → 검색 · 찾기만. 음성 변환, 다국어, 드래그 보드, 다른 리서치 데이터, 팀 협업은 뺐어요(PRD 6번).
2. **Montage 디자인 시스템과 "근거 표시 B안"** · 2026-11-19 · `953b036`
   - Montage 컴포넌트를 쓰고 원티드 로고·로딩 애니메이션은 안 써요. 요약 문장 옆 번호 → 아래 원문 카드(B안)를 기본으로, 번호 없는 A안은 사용성 테스트 비교용으로 남겼어요(이유: 문장별 근거를 사용자가 직접 확인할 수 있고 잘못 붙은 근거가 드러난다).
3. **AI 호출 실패는 화면 안 안내로, "다시 시도"는 풀릴 수 있는 실패에만** · 2026-11-23 · `8a18c8a`, `21d818f`
   - 전체 오류 화면으로 바꾸지 않아요. 키·모델·크레딧 원인은 개발 환경에서만 보여 주고 배포에서는 서버 기록에만 남겨요(결정 1).
4. **발언 번호가 없는 전사본은 규칙으로 자동 정리(AI 없음)** · 2026-11-23 · `eb38d40`, `f8984bf`, `1c5100b`
   - 원문 글자는 바꾸지 않고, 화자가 3명 이상이거나 진행자·참가자를 구분할 수 없으면 저장하지 않아요. 머리말은 저장하지 않고 알려요(결정 6의 1~4).
5. **여러 파일 올리기의 규칙** · 2026-11-23 · `d7dd002`, `c62f5c3`
   - 자리는 고른 파일 수로 세고, 10건 제한은 서버에 가기 전에 화면이 막고, 같은 참가자 파일은 첫 번째만 저장하고, 결과는 닫기 전까지 남겨요(결정 5).
6. **오류 문구 규칙과 지우기 확인 창 문구** · 2026-11-23 · `17951ae`, `13d8627`
   - 횟수에 들어가는 실패는 문구에 밝히고, 서비스 설정 문제는 배포에서 "서비스 쪽 문제라 직접 고칠 수는 없어요", 화면 용어는 "발언 번호"로 통일했어요(결정 7).
7. **해요체 통일과 "묶음"이라는 말로 통일, 합쇼체 검사 테스트** · 2026-11-23 · `8448ac0`, `bb361db`
   - `CLAUDE.md`에 해요체와 UX 문구 스킬 규칙을 적었고, 합쇼체가 다시 섞이면 `npm test`가 잡게 했어요(결정 7, 6-4b).
8. **인용의 왼쪽 세로 띠는 의도한 디자인** · 2026-11-23 · `d5128b3`
   - 디자인 훅이 지적해도 고치지 않아요. "인용"을 뜻하는 표시예요(결정 8).
9. **작은 화면: 핵심 동작만 누르는 영역을 넓히고, 번호 배지는 작게 둠** · 2026-11-23 · `dac2600`
   - 찾기·분석하기·파일 선택·번호 배지·지우기·닫기만 44px로 넓히고, 번호 배지는 보이는 크기를 그대로 두고 투명 여백으로만 넓혔어요. 320px에서만 생기는 작은 어긋남은 가로 스크롤이 아니면 기록만 해요.
10. **클로바노트 화자 확인의 규칙** · 2026-11-23 · `19b31cb`, `8e6f26a`, `4ab1764`
    - 진행자는 여러 명이어도 되고, 참가자는 한 명 이상이고, 발언 3개 이상인 참가자가 둘 이상이면 "1:1 인터뷰만"으로 막아요. 이 막힘의 우회(한 명을 진행자로 바꾸기)는 막지 않고 요약 줄에 "진행자로 고른 발언 N개는 근거로 쓰지 않아요"로 대가를 보이게 했어요.
    - **한 파일은 10,000자(녹음 약 35분)를 유지하고, 넘었을 때 "나누어 올리기"는 안내하지 않아요.** 한 인터뷰를 나누면 같은 참가자가 파일마다 다른 참가자로 잡혀 "몇 명이 말했나"가 부풀려지기 때문이에요(AI가 쓰던 기본 안내를 사람이 막음).
11. **리포트 내보내기의 범위와 문구** · 2026-11-23 · `7d91578`, `e3ba8dc`, `defe0af`
    - 새 AI 호출 없이 DB 내용만 모으고, 공유 링크와 대시보드는 만들지 않아요. 대표 인용은 서로 다른 참가자의 발언을 먼저 고르고, 근거 줄은 시스템이 한 일만 말해요("참가자 n명의 발언을 근거로 달았어요"). 전사본 건수는 "지금 올라 있는 전사본 n건", 인용이 더 있으면 "근거 N개 중 M개를 실었어요", 개인정보 안내 한 줄을 넣어요(결정 10).
12. **작업 순서와 배포 결정** · 2026-11-23 · 이 문서가 들어간 7-1 커밋
    - 6-5 마무리 → 6-7(클로바) → 6-6(방어 점검표) → 7단계. 배포는 Supabase를 같은 프로젝트로 쓰고, 주소는 테스트와 제출 때만 공유하고, 11/25까지 끝내기로 했어요.
