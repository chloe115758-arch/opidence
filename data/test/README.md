# 방어 테스트용 전사본 (가상 · 가짜 값)

업로드 화면의 방어 장면과 자동 정리를 확인하는 파일이다. **모든 내용은 직접 만든 가상 데이터이고, 연락처는 누가 봐도 가짜인 값이다**
(전화번호 `010-0000-0000`, 이메일 `test@example.com`, 주민등록번호 형태 `000000-1000000`, 이름 `김테스트`·`이테스트`). 실제 인물·연락처가 아니다.

`npm test`가 이 파일들을 `lib/transcript.ts`의 검사에 통과시켜 아래 기대 결과가 나오는지 확인한다(`lib/testdata.test.mjs`).
화면에서는 txt 파일 선택으로 하나씩 올려도 되고, 여러 개를 한꺼번에 고르거나 업로드 칸에 끌어다 놓아도 된다.
**샘플 8건(`data/interviews/`)과 함께 시험하면 라벨이 겹치거나 10건 제한에 걸릴 수 있으니, 필요하면 시크릿 창(빈 작업 공간)에서 시험하고 올린 전사본은 목록에서 지운다.**

## 화자 확인이 필요한 파일 (6-7: 고르기 전에는 저장하지 않는다)

역할을 알 수 없는 표기("참석자 N", 이름 등)가 있어 지금 규칙으로 진행자·참가자를 정할 수 없는 파일은 저장하기 전에 화자마다 역할을 고른다. 고르기 전에는 서버로 아무것도 보내지 않는다. `npm test`는 `lib/testdata.test.mjs`와 `lib/clova.test.mjs`로 아래를 확인한다.

| 파일 | 화자 목록(발언 수) | 기본으로 골라 두는 역할 | 확인할 것 |
| --- | --- | --- | --- |
| `18_화자3명.txt` | 진행자 2, 참가자 1, 김테스트 1 | 진행자, 참가자, 참가자 | 표기가 알려 주는 역할은 그대로, 모르는 표기(김테스트)는 참가자. 1줄뿐이라는 안내 |
| `19_구분불가.txt` | 김테스트 2, 이테스트 2 | 진행자, 참가자 | 모두 2줄이면 처음 말한 화자가 진행자 |
| `24_클로바노트형식.txt` | 참석자 1: 3, 참석자 2: 3, 참석자 3: 1 | 진행자, 참가자, 참가자 | 아래 |

`24_클로바노트형식.txt`는 클로바노트 내보내기 모양의 가상 파일이다(머리말 3줄 + 빈 줄 2개, `참석자 N 분:초` 줄 다음에 발언, 블록 사이 빈 줄). 이름·내용은 모두 가짜다(작성자 `김테스트`).
- 머리말 3줄(콜론이 있는 제목, 날짜 줄, 작성자)은 화자로 읽지 않고 저장하지 않는다. 결과 카드에 "머리말 3줄 제외".
- 기본 역할로 저장하면 발언 7개(진행자 3, 참가자 4), 정리 문구는 `자동 정리됨: 번호 붙임, 화자 표기 정리, 화자 역할 직접 고름, 시간 표시 7개 지움, 여러 줄 2곳 합침, 머리말 3줄 제외`. 발언 안의 "3:30쯤"은 그대로 남는다. 제목·날짜·`김테스트`·"참석자"는 저장 내용 어디에도 없다.
- 참석자 1·2를 모두 참가자로 고르면 "지금은 1:1 인터뷰만 올릴 수 있어요"로 막힌다. 모두 진행자로 고르면 "참가자를 한 명 이상 골라 주세요". 1줄뿐인 참석자 3을 진행자로 고르면 저장되고 그 발언은 근거에서만 빠진다.

번호 형식 파일(샘플 8건, `09`~`12`)은 이전과 같은 결과로 읽고 정리 문구가 나오지 않는다(`08`만 줄 합침). 같은 검사를 브라우저(올리기 전)와 서버(저장 전)에서 한다.

**10건 제한(11번째 차단) 확인**: 시크릿 창에서 샘플 8건 → `09` → `10` 순서로 올려 10건을 채운 뒤 `11`을 고른다. 자리가 0이므로 **서버에 가기 전에 화면이** "더 올릴 자리가 없어요. 목록에서 쓰지 않는 전사본을 지우고 다시 올려 주세요. 아무것도 올리지 않았어요."라고 알리고 막아야 한다. 서버(DB 트리거)의 "전사본은 10건까지 올릴 수 있어요" 안내는 다른 탭에서 동시에 올렸을 때만 보인다.

## 여러 파일을 한 번에 올릴 때의 기대 결과 (`lib/batch.test.mjs`가 확인한다)

고른 파일 수가 남은 자리(10 − 올라간 건수)보다 많으면 아무것도 올리지 않는다. 그렇지 않으면 **파일 이름 순**으로 한 개씩 저장한다(결과 카드도 같은 순서).

| 상황 | 기대 결과 |
| --- | --- |
| 빈 작업 공간에서 `01`~`09` 9개 | **"2건 저장, 7건 실패"**. `08`(참가자 A)과 `09`(참가자 Q)가 저장되고, `01`~`07`은 위 표의 안내가 파일 이름과 함께 01 → 07 순서로 나온다 |
| 샘플 8건이 있는 상태에서 `01`~`09` | "2건만 더 올릴 수 있어요. 파일을 9개 골랐으니 7개를 빼고…" 아무것도 저장하지 않는다 |
| 자리가 0인 상태에서 파일 선택 | "더 올릴 자리가 없어요" 아무것도 저장하지 않는다 |
| `10`과 `12`(둘 다 참가자 R) | "1건 저장, 1건 실패". `12`는 "참가자 R 전사본이 이미 있어요" |
| `09`·`10`·`11` | "3건 저장" |
| `13`과 `14`(둘 다 번호 없음) | "2건 저장". 서로 다른 라벨이 붙는다(예: 빈 작업 공간이면 A, B) |
| `13`과 `08`(번호 형식, 라벨 A) | `13`이 먼저 A를 가져가고 `08`은 "같은 묶음의 다른 파일에 참가자 A 라벨이 자동으로 붙었어요…"로 막힌다 |
| `interview_A.txt`를 샘플이 있는 상태에서 | "0건 저장, 1건 실패" — "이미 있어요" |

### 브라우저 확인 순서

1. **여러 파일 + 실패 카드**: 시크릿 창(빈 작업 공간)에서 `01`~`09`를 한꺼번에 고른다. 요약이 "2건 저장, 7건 실패"이고, 실패 카드 7개가 01 → 07 순서로 나오며 파일 이름·이유·고칠 방법이 있어야 한다(`04`는 한 줄에 안내 하나). 목록에는 참가자 A, Q 2건이 있다.
2. **진행 표시와 결과 유지**: 목록을 비운 뒤 `data/interviews/interview_A~H.txt` 8개를 고른다. "n/8 저장 중"이 보이고 "8건 저장"으로 끝나야 하며, 정리 문구는 없다. 결과는 닫기를 누르거나 다음 업로드를 시작할 때까지 남아 있어야 한다.
3. **끌어다 놓기**: 2번과 같은 파일들을 업로드 칸에 끌어다 놓아도 같게 동작해야 한다. 끌고 들어오면 칸 테두리 색이 바뀐다.
4. **남은 자리 초과 / 10건 제한**: 샘플 8건이 있는 상태에서 `10`, `11`, `12` 3개를 고르면 "2건만 더 올릴 수 있어요…"가 나오고 목록은 그대로다. 10건을 채운 뒤 파일을 고르면 "더 올릴 자리가 없어요"가 나온다.
5. **같은 참가자**: `10`과 `12`를 함께 고르면 "1건 저장, 1건 실패"이고 `12`는 "이미 있어요"다.
6. **자동 정리**: 빈 작업 공간에서 `13`~`17`, `21`, `23`을 올려 위 표의 정리 문구와 라벨(다음 빈 글자)을 확인한다. 전사본 화면에서 번호·역할·문장이 맞는지, `17`의 이름이 보이지 않는지 본다. `18`, `19`, `20`, `22`는 이유와 함께 막혀야 한다.
7. **번호 형식 그대로**: 샘플 8건은 정리 문구 없이 저장되고 `05`, `06`은 계속 막힌다.
8. **라벨 충돌 안내**: `13`과 `08`을 함께 올리면 `13`이 A를 가져가고 `08`에 라벨 충돌 안내가 나온다.
9. **실패 카드 유지**: 1번 상태에서 실패 카드를 둔 채 텍스트 편집기로 가서 파일을 고치고 이 탭으로 돌아와도 결과가 남아 있어야 한다. 결과는 화면 상태로만 보관하므로 같은 탭에서 다른 화면으로 이동하거나 새로 고침하면 사라진다.
10. **뒤 흐름**: 자동 정리된 전사본으로 검색 · 찾기를 해서 새 발언이 첫 검색 안내에 포함되고 인용 번호가 원문으로 이동하는지 본다.
